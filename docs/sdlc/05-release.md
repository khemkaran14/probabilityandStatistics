# 5. Release & Deployment

## Every push

CI builds a web bundle, an APK and an Android App Bundle (`.aab`) and
attaches them to the workflow run (Actions tab → run → Artifacts). Until the
signing secrets below are added they are signed with debug keys: the APK
installs on a phone for testing, but nothing can go to the Play Store.

## Google Play (Android)

1. **App id** is `com.khemkaran.chance` (Android `applicationId`/`namespace`,
   iOS bundle id). It can never change after the first upload, so change it
   before then if you want a different one.
2. **Upload key** (once, keep it safe and backed up):
   ```
   keytool -genkey -v -keystore ~/upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
   Then either:
   * **Build in CI:** add four repository secrets (GitHub → Settings →
     Secrets and variables → Actions): `ANDROID_KEYSTORE_BASE64` (output of
     `base64 -i ~/upload-keystore.jks`), `ANDROID_KEYSTORE_PASSWORD`,
     `ANDROID_KEY_ALIAS` (`upload`) and `ANDROID_KEY_PASSWORD`. Every CI run
     then attaches a signed `chance-aab` artifact.
   * **Build locally:** create `android/key.properties` (git-ignored):
     ```
     storePassword=...
     keyPassword=...
     keyAlias=upload
     storeFile=/home/you/upload-keystore.jks
     ```
     and run `flutter build appbundle --release` →
     `build/app/outputs/bundle/release/app-release.aab`.
3. **Icon and splash** are generated by `python3 tool/make_icons.py`.
4. **Play Console:** create the app and upload the `.aab` to *Internal
   testing* first. Store listing text, graphics and screenshots are in
   [docs/store](../store/listing.md).
   * Data safety: no data collected or shared (progress stays on the
     device; purchases are handled by Google Play).
   * Privacy policy: host the web build and use `…/privacy.html`.
   * Permissions used: notifications (daily reminder), run at startup
     (restores the reminder after a reboot), billing.
5. **In-app product:** Monetize → Products → In-app products → create a
   one-time product with id **`chance_premium_unlock`** and activate it. Add
   your Google account as a licence tester to buy without being charged.
6. New personal developer accounts must run a **closed test with at least
   12 testers for 14 days** before production access is granted.
7. Promote internal → closed → production once the manual checklist in
   [04-testing.md](04-testing.md) passes.

## App Store (iOS)

Needs a Mac with Xcode (or a cloud builder such as Codemagic) and an Apple
Developer account.

1. The bundle id is `com.khemkaran.chance`. In Xcode
   (`ios/Runner.xcworkspace`) choose your team and add the *In-App Purchase*
   capability.
2. App Store Connect: create the app and a **Non-Consumable** in-app
   purchase with id **`chance_premium_unlock`**.
3. `flutter build ipa --release`, upload with Xcode or Transporter, test in
   TestFlight with a sandbox account (buy and restore).

## Web

`flutter build web --release` → host `build/web` on any static host
(GitHub Pages, Netlify, Firebase Hosting). In-app purchases are not
available on web, so it works as a free preview of chapters 1–3 and the
preview lessons.

## DartPad preview

`python3 tool/make_dartpad.py` writes `dartpad_preview.dart`, a single-file
version (progress in memory, purchases always succeed) to paste into
dartpad.dev. CI fails if it is out of date.

## Versioning

`version:` in `pubspec.yaml` is `name+build`. Bump the build number on every
store upload, the name on user-visible releases, and keep `kAppVersion` in
`lib/screens/settings_screen.dart` and `CHANGELOG.md` in step.
